# 프론트엔드 디자인 개편 설계 — 베타테스트 목표

- 작성일: 2026-08-12
- 브랜치: `feature/roadmap-sns`
- 범위: **프론트엔드 전용.** 백엔드/DB/API 변경 없음
- 목표: 베타테스터에게 배포 가능한 시각적 완성도 + 모바일 대응

---

## 1. 문제 정의

사용자 진단은 "촌스럽다 / 완성도가 낮다"였다. 코드를 실측한 결과, 원인은 미감이 아니라
**디자인 시스템의 부재**였다.

| 증상 | 실측값 | 목표 |
|---|---|---|
| 폰트 크기 종류 | **20종** (12.5px 49회, 11.5/12/13/13.5px 혼재) | 7단 스케일 |
| 하드코딩 `rgba()` | **288회 / 고유 91종** | 토큰 14개 |
| 임의 `rounded-[Npx]` | 4종 + Tailwind 기본 혼용 | 4단 |
| 반응형 브레이크포인트 | **0건** (`sm:`/`md:`/`@media` 전무) | 모바일 우선 |
| 아이콘 | 이모지(🥀🎯🔑)와 SVG 혼용 | SVG 한 벌 |

`tailwind.config.ts`에 `bean`/`moss`/`bloom` 팔레트가 정의돼 있으나 화면들이 이를 사용하지 않고
`rgba(143,220,138,.13)` 형태로 직접 색을 박고 있다. 0.5px 차이의 폰트 크기가 섞이면 사용자는
"뭔지 모르겠지만 어설프다"로 인지한다. 이것이 촌스러움의 정체다.

**반응형 0건은 베타테스트에 치명적이다.** 대상이 연세대 학부생이므로 링크는 대부분 휴대폰에서
열린다. 현재 `ml-[230px]`, `w-[640px]`, `fixed left-[22px]` 등 전부 고정 픽셀이라 폰에서 레이아웃이
붕괴한다. 상세 페이지는 `fixed inset-0` 풀블리드 캔버스라 더 심하다.

## 2. 채택한 접근 (B안)

토큰 체계 수립 + 전 화면 조율 + 모바일 반응형을 **한 번에** 수행한다.

기각한 대안:
- **A안 (데스크톱 한정 정리)**: 촌스러움은 해결되나 폰에서 여전히 깨짐. 베타테스터 첫인상 실패.
- **C안 (비주얼 방향 재설계 / 아트 리터치)**: 병목이 "그림이 못생김"이 아니라 "규칙이 없음"이므로
  잘못된 곳에 투자. 베타 일정에도 부담.

반응형을 지금 함께 넣는 이유: 어차피 전 화면을 열어 고치는 작업이다. 이때 `ml-[230px]`을 토큰화만
하고 넘어가면 나중에 같은 파일을 전부 다시 열어야 한다.

## 3. 비주얼 방향 — "고도 그라디언트"

다크 포레스트를 유지하되 연세 상징색인 딥 블루를 **고도(altitude)의 의미**로 섞는다.

```
화면 상단 = 밤하늘 (연세 네이비 #0B1E3D)   <- 도달할 목표
      |  세로 그라디언트
화면 하단 = 지면 (포레스트 #06120A)        <- 지금의 나
```

콩나무 상세 페이지가 이미 세로로 기어오르는 구조이므로, **색 자체가 진행도를 말한다.** 파랑이
장식으로 얹힌 색이 아니라 의미를 갖는다는 점이 이 방향의 핵심 근거다.

**독수리 모티프**: 밤하늘 실루엣과 완주 축하 순간에만 가볍게 사용한다.

> **상표 주의**: 연세대 공식 엠블럼·워드마크·독수리 문장을 그대로 사용하지 않는다.
> 색조와 일반적 독수리 모티프 차용까지만 허용한다. 색상 자체는 상표 대상이 아니므로 문제없다.

## 4. 디자인 토큰

### 4.1 색 — 14개

**Surface (고도에 따른 배경)**

| 토큰 | 값 | 용도 |
|---|---|---|
| `sky-base` | `#0B1E3D` | 화면 상단 밤하늘 |
| `earth-base` | `#06120A` | 화면 하단 지면 |
| `surface-raised` | `rgba(10,28,42,.55)` | 카드 · 패널 |
| `surface-overlay` | `rgba(6,16,12,.86)` | 내비 · 모달 (backdrop-blur) |

페이지 배경은 공통 그라디언트를 사용한다:
`linear-gradient(180deg, #0B1E3D 0%, #0E2438 30%, #0D2119 68%, #06120A 100%)`

**Content (글자)**

| 토큰 | 값 | 용도 |
|---|---|---|
| `text-primary` | `#EAF3EE` | 제목 · 본문 |
| `text-secondary` | `#9FB6AD` | 보조 설명 |
| `text-muted` | `#7D968C` | 메타 · 캡션 |

세 값 모두 네이비 배경과 포레스트 배경 양쪽에서 동작하도록 냉중립(cool-neutral)으로 잡았다.
배경별로 텍스트 램프를 나누지 않는다.

**Accent (의미를 가진 색)**

| 토큰 | 값 | 의미 |
|---|---|---|
| `growth` | `#5DB35B` | 진행 · 완료 · 콩나무 = **지금의 나** |
| `growth-bright` | `#8FDC8A` | 잎 · 강조된 진행률 |
| `goal` | `#2F6FBF` | 주요 버튼 = **도달할 목표** |
| `goal-bright` | `#7CC4F0` | 링크 · 포커스 링 · 활성 탭 |
| `bloom` | `#E2B94F` | 완주 축하 · 콩 화폐 |
| `wither` | `#D8B078` | 시듦 · 기한 초과 |

**Line**

| 토큰 | 값 | 용도 |
|---|---|---|
| `line` | `rgba(140,180,220,.17)` | 테두리 — **기존 rgba 91종을 대체** |

### 4.2 타입 스케일 — 7단

| 토큰 | 크기 | 서체 | 용도 |
|---|---|---|---|
| `display` | 30 | Gowun Batang (serif) | 페이지 타이틀 |
| `title` | 20 | Gowun Batang (serif) | 로드맵 제목 |
| `heading` | 17 | IBM Plex Sans KR | 섹션 헤딩 |
| `body` | **15** | IBM Plex Sans KR | 본문 기본 |
| `body-sm` | 13.5 | IBM Plex Sans KR | 보조 본문 |
| `caption` | 12 | IBM Plex Sans KR | 메타 정보 |
| `micro` | 10.5 | IBM Plex Sans KR | 뱃지 · 라벨 |

**본문 기본을 12.5px에서 15px로 올린다.** 현재 12.5px가 49회 쓰여 사실상 본문 기본값인데, 이것이
"완성도 낮아 보임"의 가장 큰 단일 원인이며 모바일에서는 가독성이 무너진다.

> **파급 효과**: 모든 화면의 세로 길이가 늘어난다. 카드 높이, `line-clamp` 줄 수, 그리드 최소폭을
> 함께 재조정해야 한다. 이 조정을 생략하면 레이아웃이 깨진다.

### 4.3 간격 · 반경

- **간격**: Tailwind 기본 4px 스케일을 그대로 쓴다. 임의값(`px-[18px]`, `mt-[9px]`) 사용을 금지한다.
- **반경**: `sm` 8 / `md` 12 / `lg` 16 / `xl` 20 / `full`

### 4.4 아이콘

이모지를 UI 크롬(chrome)에 쓰지 않고 SVG 한 벌로 통일한다.
`SideNav`의 기존 SVG(`SproutIcon`/`ForestIcon`/`SeedIcon`/`BeanIcon`/`CalendarIcon`) 스타일을 기준으로
삼고, 시듦/대목표/로그인 등에 쓰인 이모지를 SVG로 교체한다.

**예외**: `user.avatar_emoji`는 사용자가 고른 콘텐츠 데이터이므로 이모지 그대로 유지한다.

## 5. 반응형 전략

모바일 우선으로 토큰을 설계하고 그 위에 데스크톱을 얹는다. Tailwind 기본 브레이크포인트를 쓴다.

### 5.1 앱 셸

| 뷰포트 | 내비게이션 |
|---|---|
| `< 768px` | **하단 탭바** — 숲 / 일정 / **＋(씨앗 심기, 중앙 FAB)** / 랭킹 / 내 콩나무 |
| `>= 768px` | 좌측 레일 (현재 `SideNav` 구조 유지) |

전환점을 768px로 잡는다(브라우저 목업에서는 1024px로 표기했으나 768px로 확정).
레일 폭 168px를 빼도 768px 뷰포트에 본문 600px가 남아 태블릿 세로에서도 레일이 성립하며,
브레이크포인트를 하나만 두는 편이 유지보수에 유리하다.

중앙 ＋ 를 씨앗 심기에 배정하는 이유: 제품의 핵심 행동이며 엄지 도달 범위의 중심이다.

하단 탭바는 `env(safe-area-inset-bottom)`을 반영해 iOS 홈 인디케이터와 겹치지 않게 한다.

### 5.2 기존 버그 해소

현재 `SideNav`는 `fixed left-[22px] w-[168px]`로 x 22~190을 점유하는데 페이지들은 `w-[640px] mx-auto`
중앙 정렬이라 **뷰포트 1020px 미만에서 내비가 본문 왼쪽을 덮어 첫 요소 클릭이 차단된다**.
`/new`, `/privacy`는 커밋 `a3a26e6`에서 클램프로 임시 처리했고, `/goal/[id]`, `/roadmap/[id]`는 미해결이다.

`AppShell`이 레일 폭을 레이아웃으로 확보하면(고정 오버레이가 아니라 flex/grid 컬럼) 이 버그는
구조적으로 사라진다. 기존 클램프 임시 코드도 함께 제거한다.

### 5.3 캔버스 페이지

`BeanstalkCanvas`(419줄)는 지오메트리를 전부 내부에 갖고 있고 고정 픽셀 기반이다.
뷰포트 폭에 비례하도록 스케일 계산을 도입하고, 하단 탭바 높이만큼 안전 여백을 확보한다.
세로 스크롤 월드 자체는 모바일에 오히려 잘 맞으므로 구조는 유지한다.

## 6. 컴포넌트 정리

현재 모든 페이지가 버튼·칩·카드·입력창을 각자 인라인으로 그린다. 이것이 rgba 91종의 직접 원인이다.
토큰만 만들고 이 작업을 생략하면 동일한 드리프트가 재발한다.

`components/ui/` 아래 프리미티브 10종을 신설한다.

| 컴포넌트 | 변형 | 현재 중복 위치 |
|---|---|---|
| `Button` | primary / secondary / ghost / danger, sm·md | 전 페이지 인라인 |
| `Chip` | 라벨 / 토글 | 피드 탭, `FieldChips`, 뱃지 |
| `Card` | — | 피드 카드, 프로필 그리드, 패널 |
| `Field` | input / textarea + 라벨 + 에러 | login·signup·verify·reset 4곳 |
| `Modal` | — | `MilestonePostModal`, `BeanShopModal` |
| `ProgressBar` | — | 피드 카드, 상세, 프로필 |

| `Tabs` | — | 전체/팔로잉, 프로필 |

## 8. 검증 방법

**매 단계마다:**

1. `npx tsc --noEmit` + `npm run lint` + `next build`
   - **dev 서버를 내린 뒤 빌드할 것.** 켜둔 채 빌드하면 `.next`를 덮어써 CSS 404가 발생한다.
     빌드 후 `.next` 삭제 + 재기동이 안전하다.
2. **스크린샷 매트릭스** — chrome-devtools로 **390px / 768px / 1280px** 3종 뷰포트 캡처, before/after 비교

**최종:**

3. **골든 패스 회귀** — 로그인 → 씨앗 심기 → 심기 → 상세 → 마일스톤 체크 → 일정 콩 체크 → 랭킹
4. **WCAG AA 대비비(4.5:1)** 검사 — 토큰 확정 시 1회
5. 백엔드 `pytest` 1회 (프론트 전용 작업이라 영향은 없으나 확인)

**API 비용**: 0원. `/new` 흐름은 `MockClaudeClient`로 재현한다(`use_real_llm`이 꺼지면 결정론적으로
질문 5개 + 로드맵 2개 세트를 반환). 현재 Anthropic 크레딧이 소진돼 있으나 이 작업에는 무관하다.
